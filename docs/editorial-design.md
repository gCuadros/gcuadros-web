# Graphic, multipage portfolio

The current site uses real pages: Home, Projects, Blog and About, each in Spanish and English. Home introduces Gonzalo and provides selected routes into his public work. Experience, education, talks and the downloadable CV live on About. Projects contains the public Hevy case; Blog contains the existing CI essay, now maintained as Markdown.

The identity uses warm paper (#F5F2EA), near-black ink (#22231F), burnt-orange links (#A83213), bright orange (#FF764B), lilac and moss panels. Bricolage Grotesque provides large expressive headings, Manrope provides readable prose, and IBM Plex Mono labels code and small metadata. Fonts are self-hosted and licensed through the pinned Fontsource packages. Social previews and the favicon share the palette.

The homepage layer explorer is a functional React interaction: selecting Interface, Validation or Production changes the visible diagram and explanation. It is a conceptual illustration, not a company architecture or live monitor. Keyboard buttons expose the selected state and announce updated text. CSS animates the layers, link arrows and name entrance. Same-origin document transitions progressively enhance ordinary page links in supporting browsers; article titles retain their visual identity while moving from the index into the article. Reduced-motion preferences disable movement. Without JavaScript, reading, routes, language switching and downloads remain available; the diagram explains its fallback.

Responsive layouts are reviewed at 320, 390, 768 and 1440 px. Diagrams and typography are built with HTML/CSS; no animation framework, stock dashboard or invented project screenshots are used. Accessibility checks complement visual review, not replace it.

Maggie Appleton’s https://maggieappleton.com/ informed the emphasis on authored material and reading hierarchy. This implementation does not copy her illustrations, fonts or layout. The user authorized direct code design for this iteration. The older local Pen.dev Q/R boards describe the previous design and are not the source of truth for this version. Do not claim they were synchronized.

Public content must not include team headcounts, internal migration paths or company infrastructure diagrams. Technical leadership must not imply formal people management. AWS, Azure, Kubernetes and Ansible remain academic training unless professional use is explicitly confirmed.
