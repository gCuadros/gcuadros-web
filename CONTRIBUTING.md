# Contribuir

Usar ramas cortas `feat/`, `fix/`, `chore/` o `docs/` y abrir una PR por objetivo. No trabajar directamente en `main`.

Commits con Conventional Commits: `feat: add experience section`, `fix: improve keyboard navigation`. Explicar el propósito del cambio; evitar commits de actualizaciones inconexas.

Antes de abrir una PR: ejecutar `npm run check`, revisar el diff y comprobar la interfaz cuando corresponda. Añadir pruebas de comportamiento para funcionalidades interactivas; no pruebas que solo repliquen contenido estático.

Las PR deben describir el problema, el resultado, la validación y cualquier limitación. Fusionar mediante squash con un título semántico. Nunca incluir credenciales o información confidencial de empleadores.
